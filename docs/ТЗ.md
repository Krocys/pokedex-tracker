# Техническое задание

## 1. Общие положения

**Наименование системы:** «Покедекс-трекер» — веб-приложение для учёта прогресса сбора покедекса.

**Назначение:** автоматизация процесса учёта коллекции покемонов. Система заменяет разрозненные заметки, скриншоты и электронные таблицы единым интерактивным средством, в котором пользователь отмечает наличие каждой формы покемона, получает списки недостающих экземпляров и сведения о том, где эти экземпляры можно получить.

**Цели создания системы:**

- Обеспечить ведение нескольких независимых профилей сбора с привязкой к конкретным играм серии и с выбором типа покедекса.
- Сократить затраты времени на ручную сверку сведений за счёт поиска, фильтрации и сортировки по типам, поколениям, формам и текущему состоянию.
- Предоставить справочные сведения в контексте выбранной игры: места поимки и эволюционные линии без сведений, не относящихся к текущему профилю.
- Обеспечить количественную оценку прогресса и наглядное представление оставшегося объёма работ.
- Разграничить права пользователей системы в соответствии с выполняемыми ими функциями.

## 2. Функциональные требования

### 2.1. Модуль регистрации и авторизации

- **ФТ-1.** Регистрация нового пользователя с проверкой корректности заполнения полей формы.
- **ФТ-2.** Вывод пользователю сообщений о результате проверки каждого поля.
- **ФТ-3.** Сохранение данных зарегистрированного пользователя в базе данных.
- **ФТ-4.** Авторизация с проверкой наличия учётной записи в базе данных.
- **ФТ-5.** Запрет повторной авторизации при наличии активного сеанса.
- **ФТ-6.** Переход в личный кабинет, соответствующий роли пользователя.
- **ФТ-7.** Завершение сеанса и выход из личного кабинета.

### 2.2. Модуль управления профилями покедексов

- **ФТ-8.** Создание профиля с указанием наименования, игры либо национального покедекса, типа покедекса и признака shiny.
- **ФТ-9.** Поддержка трёх типов покедекса: только финальные формы, живой покедекс, живой покедекс со всеми формами.
- **ФТ-10.** Просмотр списка профилей, переключение активного профиля, переименование и удаление.
- **ФТ-11.** Независимый учёт прогресса по каждому профилю.
- **ФТ-12.** Замена изображений на shiny-вариант при включённом соответствующем признаке профиля.

### 2.3. Модуль просмотра покедекса

- **ФТ-13.** Вывод покемонов активного профиля в виде карточек с изображением, номером, наименованием, типами и текущим состоянием.
- **ФТ-14.** Отметка состояния покемона одним из трёх значений: не получен, имеется предэволюция, получен.
- **ФТ-15.** Поиск по наименованию и номеру.
- **ФТ-16.** Фильтрация по типу, поколению, состоянию и форме.
- **ФТ-17.** Сортировка по номеру в покедексе, национальному номеру и наименованию.
- **ФТ-18.** Постраничный вывод списка.

### 2.4. Модуль просмотра сведений о покемоне

- **ФТ-19.** Вывод сведений о покемоне: изображений, типов, номеров в покедексах.
- **ФТ-20.** Вывод мест поимки, относящихся исключительно к игре активного профиля.
- **ФТ-21.** Формирование ссылки на поиск видеоматериалов по данному покемону и игре.
- **ФТ-22.** Вывод эволюционной линии с указанием условий эволюции и принадлежности звеньев к активному покедексу.

### 2.5. Модуль статистики

- **ФТ-23.** Расчёт количества и доли полученных покемонов по активному профилю.
- **ФТ-24.** Расчёт количества покемонов, для которых имеется предэволюция.
- **ФТ-25.** Разбивка прогресса по поколениям и типам.
- **ФТ-26.** Графическое представление прогресса.

### 2.6. Модуль администрирования

- **ФТ-27.** Просмотр списка зарегистрированных пользователей.
- **ФТ-28.** Изменение роли пользователя, блокировка и удаление учётной записи.
- **ФТ-29.** Дополнение и редактирование справочных сведений о местах поимки.
- **ФТ-30.** Ограничение доступа к разделам приложения в соответствии с ролью пользователя.

## 3. Пользовательские роли и права

### 3.1. Пользователь

- Регистрация и авторизация в системе.
- Создание, изменение и удаление собственных профилей покедексов.
- Отметка состояния покемонов в собственных профилях.
- Просмотр справочных сведений и статистики по собственным профилям.

### 3.2. Менеджер

- Все права роли «Пользователь».
- Дополнение и редактирование сведений о местах поимки покемонов.
- Внесение сведений для игр, по которым сведения во внешнем источнике отсутствуют.
- Просмотр перечня покемонов, сведения о местах поимки которых не заполнены.

### 3.3. Администратор

- Все права роли «Менеджер».
- Просмотр списка зарегистрированных пользователей.
- Изменение ролей пользователей.
- Блокировка и удаление учётных записей.
- Просмотр сводной статистики по системе.

## 4. Технические требования

### 4.1. Frontend

- Языки разработки: HTML, CSS, JavaScript. Применяются модули стандарта.
- Среда выполнения: браузеры.
- Адаптивная вёрстка с поддержкой мобильных устройств, планшетов и персональных компьютеров.
- Постраничный вывод списка покемонов и отложенная загрузка изображений для обеспечения быстродействия при объёме справочника свыше тысячи записей.

### 4.2. Backend

- На текущем этапе разработки серверная часть не реализуется. Приложение выполняется полностью на стороне клиента.
- Справочные сведения хранятся в файлах формата JSON и доступны только для чтения. Сведения пользователей хранятся в локальном хранилище браузера.
- Доступ к обоим видам сведений осуществляется через единый программный интерфейс, что допускает последующую замену локального хранилища на взаимодействие с сервером без изменения остальных модулей приложения.
- Источник справочных сведений: открытый программный интерфейс PokeAPI. Выгрузка выполняется предварительно, отдельным сценарием, и не производится во время работы приложения.
- Сведения о местах поимки для игр восьмого и девятого поколений во внешнем источнике отсутствуют и вносятся вручную пользователями с ролью «Менеджер».

### 4.3. Безопасность

- Пароли пользователей хранятся исключительно в виде хеш-значений с использованием соли.
- Проверка корректности вводимых данных выполняется до их сохранения.
- Доступ к разделам приложения ограничивается в соответствии с ролью пользователя.
- Повторная авторизация при наличии активного сеанса не допускается.

## 5. Интерфейс системы

Для интерфейса системы используется пастельная цветовая схема, построенная на основе фирменных цветов предметной области — красного, синего, белого и чёрного — с пониженной насыщенностью. Пастельные тона выбраны для того, чтобы оформление не конкурировало по яркости с цветовыми обозначениями типов покемонов, которые выводятся на карточках.

Предусматриваются две темы оформления, переключаемые пользователем.

Основная (светлая) тема:  
— фон страницы: `#FFFBF4`;  
— поверхность карточек: `#FFFFFF`;  
— подложка панелей: `#F6F1E7`;  
— основной текст: `#35322E`;  
— второстепенный текст: `#6E6862`;  
— границы: `#E6DED1`;  
— акцентный цвет: `#F2A79F`;  
— дополнительный цвет: `#A9C9E4`;  
— цвет сообщений об ошибках: `#C25B52`.

Ночная (тёмная) тема:  
— фон страницы: `#24272E`;  
— поверхность карточек: `#30343C`;  
— подложка панелей: `#1E2127`;  
— основной текст: `#EDEAE3`;  
— второстепенный текст: `#A6A9B0`;  
— границы: `#3C414A`;  
— акцентный цвет: `#E39199`;  
— дополнительный цвет: `#93B6DE`;  
— цвет сообщений об ошибках: `#E58880`.

Текущее состояние покемона обозначается цветом подложки карточки: не получен — нейтральный тон (`#F6F1E7` в светлой теме, `#2A2E35` в тёмной), имеется предэволюция — песочный (`#F6E3C4` и `#453A28` соответственно), получен — приглушённый зелёный (`#D8E8D3` и `#2C3D2E`).

### 5.1. Главная страница

- Навигационное меню, включающее в себя: логотип, ссылки на разделы «Покедекс», «Мои профили», «Статистика», кнопки входа и регистрации.
- Шапка страницы с наименованием системы.
- Содержательная часть с кратким описанием возможностей системы.
- Подвал со сведениями о разработчике и указанием источника справочных данных.

### 5.2. Страница покедекса

- Панель фильтров: тип, поколение, состояние, форма.
- Поле поиска по наименованию и номеру.
- Элемент выбора порядка сортировки.
- Сетка карточек покемонов с указанием состояния.
- Элементы постраничной навигации.

### 5.3. Страница сведений о покемоне

- Изображение покемона, его наименование, типы и номера в покедексах.
- Перечень мест поимки для игры активного профиля.
- Ссылка на поиск видеоматериалов.
- Схема эволюционной линии с возможностью перехода к другим её звеньям.

### 5.4. Личный кабинет

- Личный кабинет пользователя: список профилей, показатели прогресса, настройки учётной записи.
- Личный кабинет менеджера: формы дополнения и редактирования сведений о местах поимки, перечень незаполненных сведений.
- Личный кабинет администратора: список пользователей с возможностью изменения роли, блокировки и удаления, сводная статистика по системе.
